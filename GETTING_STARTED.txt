REBUILDING FROM THIS ARCHIVE
============================

OPTION 1 — Deploy to a new VPS (recommended)
---------------------------------------------
1. Extract this archive somewhere on your laptop.
2. Read `deploy/Dr-Tea-Deployment-Guide.html` in your browser (full step-by-step).
3. Buy a VPS (Hetzner CX22 €4/mo or DigitalOcean Basic $6/mo).
4. SSH into the VPS as root.
5. Either:
   a) Push this folder to a GitHub repo and run:
        curl -fsSL https://raw.githubusercontent.com/USER/REPO/main/deploy/install.sh | bash
   b) Or SCP this folder to the VPS and run install.sh from there:
        scp -r . root@VPS_IP:/opt/drtea-source
        ssh root@VPS_IP "cd /opt/drtea-source && bash deploy/install.sh"
6. Point your domain's DNS A record to the VPS IP. Done.


OPTION 2 — Run locally for development
---------------------------------------
Requirements: Node.js 20+, pnpm, Docker (for Postgres).

1. Extract this archive.
2. Install dependencies:
     pnpm install
3. Start a local Postgres (in another terminal):
     docker run --name drtea-pg -e POSTGRES_PASSWORD=dev -p 5432:5432 -d postgres:16
4. Set environment variables (create artifacts/api-server/.env):
     DATABASE_URL=postgresql://postgres:dev@localhost:5432/postgres
     SESSION_SECRET=any-random-string-32chars-or-more
     ADMIN_PASSWORD=admin
5. Run the services:
     pnpm --filter @workspace/api-server run dev    # Backend (port 8080)
     pnpm --filter @workspace/dr-tea run dev        # Frontend (port from PORT env)
6. Visit the URL printed by the dr-tea workflow.


See `deploy/Dr-Tea-Deployment-Guide.html` for full details on both methods.


DATABASE
========
The app uses PostgreSQL via Drizzle ORM.

- Schema/models live in: artifacts/api-server/src/lib/*.ts
- DB connection helper: artifacts/api-server/src/lib/db.ts
- Migrations run automatically on first boot of the api container
  (see Dockerfile + entrypoint)
- Auto-generated by install.sh on the VPS:
    POSTGRES_PASSWORD, DATABASE_URL, SESSION_SECRET, ADMIN_PASSWORD
  All stored in /opt/drtea/.env on the server.

To back up the production database:
    ssh root@VPS_IP "docker exec drtea-pg pg_dump -U postgres postgres" > backup.sql

To restore:
    cat backup.sql | ssh root@VPS_IP "docker exec -i drtea-pg psql -U postgres postgres"


HEALTH CHECK
============
After any deploy, this URL should return 200 OK:
    https://your-domain.com/api/healthz
    → {"status":"ok"}

If it doesn't, the install/update script auto-rolls back to the last
known-good commit. You can also roll back manually any time with:
    drtea rollback
